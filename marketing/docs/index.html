EasyHost docs

Everything on EasyHost runs through the ezhst CLI, which is built to be driven by coding agents. This page covers every command.

Quick start

For agents

Install the skill in your project, then ask your agent (Claude Code, Cursor, Codex or any other) to deploy.

npx ezhst skill install

Then tell it: Deploy this to EasyHost. The agent creates an account if you do not have one, creates and links a project, sets environment variables and deploys.

For humans

Install the CLI globally or run it with npx.

npm i -g ezhst

Create an account (or log in), link your Next.js project folder and deploy.

npx ezhst register
npx ezhst link
npx ezhst deploy

Already have an account? Use npx ezhst login instead of register. You can also sign up in the dashboard.

Installing the agent skill

The skill is a single SKILL.md file that teaches your agent how to use EasyHost.

ezhst skill installWrites .claude/skills/easyhost/SKILL.md in the current project.
ezhst skill install --globalWrites ~/.claude/skills/easyhost/SKILL.md, available in every project.

Use the project install when you want the skill checked into the repo for your team. Use --global to make it available everywhere on your machine.

For agents that do not load skill folders, give them the raw file at https://easyhost.fun/skill.md, for example by adding it to your agent's rules or instructions file.

Authentication

ezhst register --name <name> --email <email> --password <password>Create an account. A "Default project" is created and a verification email is sent.
ezhst login --email <email> --password <password>Log in.
ezhst logoutLog out.
ezhst whoamiShow the logged in account.
ezhst resend-verificationSend the verification email again.
ezhst forgot-password --email <email>Send a password reset link.

login and register save your token in ~/.easyhost/config.json. In CI or agent sandboxes, provide the token with the EZHST_TOKEN environment variable instead.

EZHST_TOKEN=<token> npx ezhst deploy --json

Output and prompts

  • Every command accepts --json for machine readable output. Agents should always use it.
  • In a terminal, missing values are asked for interactively. Without a TTY the CLI never prompts: it fails with a message naming the missing flag.

Projects and linking

A project is one app plus its storage bucket, database, email sender and API keys. The project name becomes its subdomain: <slug>.easyhost.fun.

ezhst projects listList your projects.
ezhst projects create <name>Create a project.
ezhst projects infoStatus, URL, env, build settings, domains and recent deployments.
ezhst projects rename <name>Change the display name. The URL stays the same.
ezhst projects delete --yesDelete the app, deployments, storage, database, email and API keys.
ezhst link [--project <slug>]Link the current folder to a project (writes .easyhost.json).

Project-scoped commands use the project linked in .easyhost.json. Pass --project <slug> to any of them to target another project.

ezhst projects create my-app
ezhst link --project my-app

Deploying

ezhst deploy [--verbose]Package the Next.js project in the current folder, upload, build and go live.
ezhst redeploy [--verbose]Rebuild the latest upload. Use after changing env vars or build settings.
ezhst startStart the app.
ezhst stopStop the app.
ezhst deployments listList deployments.

What gets uploaded

deploy uploads your project source. It skips node_modules, .next, .git and every .env* file. No changes to your project are needed.

Environment variables are not read from your .env files. Set them with ezhst env set or ezhst env import .env before deploying.

Your app is live at https://<slug>.easyhost.fun once the build finishes.

Environment variables

Variables are applied on the next deploy or redeploy.

ezhst env listList variables.
ezhst env set KEY=VALUE [KEY=VALUE...]Set one or more variables.
ezhst env unset KEY [KEY...]Remove one or more variables.
ezhst env import <file>Merge the variables from a .env file.
ezhst env set NEXT_PUBLIC_SITE_URL=https://my-app.easyhost.fun
ezhst env import .env.production
ezhst redeploy

Build settings

Empty settings are auto-detected, which works for most Next.js projects.

ezhst build showShow the current settings.
ezhst build set [--node 20|22|24] [--root-dir <dir>] [--install <cmd>] [--build <cmd>] [--start <cmd>]Override one or more settings. Pass "" to reset a field to auto.
ezhst build resetReset every setting to auto.

Auto-detection

SettingDefault
Node versionengines.node in package.json, otherwise 24
Package managerFrom your lockfile
Start commandnext start -H 0.0.0.0 -p $PORT
 
ezhst build set --node 22 --root-dir apps/web
ezhst build set --install ""
ezhst redeploy

Logs and build logs

ezhst logs [--tail <lines>]Runtime logs from the running app.
ezhst deployments log [deploymentId]Full build log. Defaults to the latest deployment.

When a deploy fails, read the build log, fix the cause and run ezhst deploy again.

ezhst deployments log --json
ezhst logs --tail 200

Storage S3 compatible

Each project gets one bucket. Files are public by URL.

ezhst storage infoBucket, public base URL and S3 credentials.
ezhst storage create <name>Create the bucket.
ezhst storage rotate-keysIssue new S3 credentials.
ezhst storage ls [prefix]List files.
ezhst storage upload <files...> [--prefix <path/>]Upload files.
ezhst storage download <key> [output]Download a file.
ezhst storage rm <key>Delete a file.
ezhst storage delete --yesDelete the bucket.

Using it from your app

Run ezhst storage info, store the credentials with ezhst env set, then use any S3 client. The endpoint is https://storage.easyhost.fun, the region is us-east-1 and requests must use path-style URLs.

lib/storage.ts
import { S3Client, PutObjectCommand } from "@aws-sdk/client-s3";

export const s3 = new S3Client({
  endpoint: "https://storage.easyhost.fun",
  region: "us-east-1",
  forcePathStyle: true,
  credentials: {
    accessKeyId: process.env.S3_ACCESS_KEY_ID!,
    secretAccessKey: process.env.S3_SECRET_ACCESS_KEY!,
  },
});

export const uploadAvatar = async (userId: string, body: Buffer) => {
  await s3.send(
    new PutObjectCommand({
      Bucket: process.env.S3_BUCKET!,
      Key: `avatars/${userId}.png`,
      Body: body,
      ContentType: "image/png",
    }),
  );
};

The file is then served at the public base URL from storage info followed by its key.

Database Postgres

Each project gets one managed Postgres database.

ezhst db infoConnection string, shadow connection string and tables.
ezhst db create <name>Create the database.
ezhst db query "<sql>"Run a SQL statement.
ezhst db query --file <file.sql>Run a SQL file.
ezhst db rows <table> [--page <n>]Browse rows in a table.
ezhst db reset-passwordRotate the password and print the new connection string.
ezhst db delete --yesDelete the database.

Connecting your app

Copy the connection string from ezhst db info into your app's environment. It works with Prisma, Drizzle or any Postgres client.

ezhst db create main
ezhst db info --json
ezhst env set DATABASE_URL="postgresql://..."

Prisma migrations

prisma migrate dev needs a shadow database. Use the shadow connection string from ezhst db info.

prisma/schema.prisma
datasource db {
  provider          = "postgresql"
  url               = env("DATABASE_URL")
  shadowDatabaseUrl = env("SHADOW_DATABASE_URL")
}

After ezhst db reset-password, update DATABASE_URL with ezhst env set and run ezhst redeploy.

Email

Send transactional email from <username>@easyhost.fun. Each project has one sender and can send 100 emails per day.

ezhst email infoSender address and usage.
ezhst email sender create <username>Create the sender address.
ezhst email sender deleteDelete the sender.
ezhst email send --from <address> --to <address> --subject <text> (--text <body> | --html <html>)Send an email.
ezhst email logs [--page <n>]List sent emails.
ezhst email sender create hello
ezhst email send --from hello@easyhost.fun --to ada@example.com --subject "Welcome" --text "Thanks for signing up."

Sending from your app

Apps send email over HTTP with an API key. Send text or html.

POST https://api.easyhost.fun/api/v1/email/send
const res = await fetch("https://api.easyhost.fun/api/v1/email/send", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.EASYHOST_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    from: "hello@easyhost.fun",
    to: "ada@example.com",
    subject: "Welcome",
    html: "<p>Thanks for signing up.</p>",
  }),
});

API keys

API keys authenticate your app against the HTTP email API.

ezhst keys listList keys.
ezhst keys create <name>Create a key. It is shown only once.
ezhst keys revoke <id>Revoke a key.
ezhst keys create production --json
ezhst env set EASYHOST_API_KEY=<key>
