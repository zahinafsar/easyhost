# EasyHost Project Memory

## Current state (2026-09-26)
- Layout: client/ (Vite dashboard), server/ (Hono API), cli/ (`ezhst`, npm package ezhst), marketing/ (static HTML+CSS), infra/ (caddy, userdb), scripts/start.mjs
- Env: a single root `.env` both locally and on the VPS (no `.env.production`; templates `.env.example` and `.env.production.example`). No fallbacks anywhere; server validates via server/src/lib/env.ts, client via client/src/lib/env.ts. `npm start` refuses empty or `<PLACEHOLDER>` values
- Fixed values are code constants: LIMITS (10 apps, 10 buckets, 10 databases, 10 email senders, 100 emails/day, 1 concurrent build), API port 48710, EMAIL_DOMAIN easyhost.fun, bucket easyhost-deploys, docker network easyhost, MinIO user easyhost
- Local ports: API 48710, dashboard 51730, postgres 127.0.0.1:54329, userdb 127.0.0.1:54330, minio 127.0.0.1:19000/19001, caddy :80 (admin 127.0.0.1:20190)
- MinIO images: pgsty/minio + pgsty/mc (official images are no longer public)

## Production (VPS luggora, 65.181.123.115)
- Nginx Proxy Manager owns 80/443 and terminates TLS; user chose to keep NPM in front (rejected Caddy as front door)
- EasyHost Caddy has no host ports, joins NPM network (PROXY_NETWORK) as `easyhost-caddy`, serves marketing, dashboard (/api proxied same-origin), api., storage., app subdomains
- Caddy admin is a unix socket shared only with the API container; API re-syncs app routes on boot and every 60s (no --resume)
- userdb publishes 5432 directly; TLS cert for db.easyhost.fun issued in NPM and mounted read-only (NPM_LETSENCRYPT_DIR, USERDB_CERT_NAME), reloaded every 6h
- Custom app domains: API creates NPM certificate then proxy host via NPM API (dedicated NPM user with "Created Items Only" recommended); EDGE_PROXY=none locally

## Features
- Deploy: CLI uploads source tarball; Postgres-backed build queue; image built from node:22-alpine (install by lockfile, build, next start); step-based CLI output; build log in Deployment.log
- Storage: S3 compatible, no custom storage API (v1 storage removed). Each bucket gets a MinIO service account (access/secret key on Bucket row) with an inline policy scoped to that bucket, created/rotated/removed by shelling out to `mc` (MC_HOST_eh env). API image copies mc from pgsty/mc; local dev needs mc on PATH. S3 endpoint = STORAGE_PUBLIC_URL, path-style, region us-east-1, bucket name = minioName eh-<id>. All files public by URL. Dashboard file browser still works via root MinIO client
- Databases: shared Postgres, one db_<hex> + role u_<hex> each, plus <db>_shadow for prisma migrate dev; console + table editor run as the owner role
- Email: sender addresses <username>@easyhost.fun (reserved names blocked); send API requires `from`

## Preferences
- No backward compatibility or backfills (pre-launch)
