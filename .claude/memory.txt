# EasyHost Project Memory

## Recent Changes
- Initial build (2026-09-25)
  - Infra: docker-compose with postgres:16 (5434), MinIO official images (Docker Hub minio/minio, minio/mc, quay.io/minio) are no longer public. Using community builds pgsty/minio:RELEASE.2026-08-04T00-00-00Z and pgsty/mc:RELEASE.2026-09-16T00-00-00Z in both compose files; no MinIO healthcheck (image contents unknown), minio-init retries `mc alias set` until MinIO is up, then `mc mb easyhost-deploys`
  - Caddy runs from JSON config (`infra/caddy/caddy.json`) with `--resume`, server name `apps`, automatic HTTPS disabled for local `*.localhost`
  - Prisma models: User, ApiKey, Bucket, SqliteDatabase, EmailLog, App, Deployment. Migration `init` applied
  - Storage buckets map to MinIO buckets `eh-<bucketId>`
  - Email API sends from shared `EMAIL_FROM` via Resend, logs every attempt to EmailLog, `EMAIL_DAILY_LIMIT` per user per 24h
  - Env var changes require a redeploy (`POST /api/apps/:id/redeploy` reuses the latest successful artifact)
  - Client imports `AppType` directly from `../../../../server/src/index.ts` for the typed Hono client
- Deploys switched to server-side source builds (no `output: "standalone"` needed): CLI uploads source, Dockerfile installs by lockfile, runs build, `next start`. App env vars are Docker build args (so NEXT_PUBLIC_* work) and runtime env. `.env*` files are excluded from the upload
- Deployment.step (QUEUED, PREPARING, INSTALLING, BUILDING, STARTING, ROUTING, DONE) is set by the pipeline; INSTALLING/BUILDING are detected from Docker "Step N/M : RUN" lines of our generated Dockerfile. CLI shows ora spinners per step, prints a filtered log tail on failure, `--verbose` streams the full log. Migration `add_deployment_step` applied
- CLI npm package and bin renamed to `ezhst`. Config paths (`~/.easyhost/config.json`, `.easyhost.json`) intentionally unchanged. `EASYHOST_API_URL` env was removed; API URL comes from `ezhst login --api` saved config, else `PRODUCTION_API_URL`. With asdf, run `asdf reshim nodejs` after `npm link`
- Ports moved off defaults (2026-09-25): API 48710, dashboard dev 51730, postgres 127.0.0.1:54329, minio 127.0.0.1:19000/19001, caddy admin 127.0.0.1:20190 (dev). Caddy no longer uses --resume; API re-syncs RUNNING app routes on start and every 60s
- Production: `npm start` at repo root runs scripts/start.mjs (creates root .env secrets) then `docker compose -f docker-compose.prod.yml up -d --build`. Domains: easyhost.fun (marketing/ static HTML+CSS), app.easyhost.fun (dashboard, /api proxied same-origin), api.easyhost.fun, storage.easyhost.fun (MinIO, presigned URLs signed for this host via MINIO_PUBLIC_*), <slug>.easyhost.fun apps. CLI default API URL is https://api.easyhost.fun
- No env fallbacks anywhere (global rule). server/src/lib/env.ts throws listing all missing vars on boot; client/src/lib/env.ts requires VITE_PUBLIC_API_URL (root .env via Vite envDir for dev, compose build arg for prod); .env parser for the dashboard lives in client/src/lib/dotenv.ts; scripts/start.mjs exits if required root .env values are empty
- Build queue added: `server/src/lib/build-queue.ts`, required env `BUILD_CONCURRENCY` (1 for now, also in prod compose). Deployment detail returns `queuePosition`; CLI shows "Waiting in queue (N ahead)" and exits cleanly when its deploy is SUPERSEDED. Single API process assumed for the in-memory active counter
- Production env consolidated into root `.env.production` (all 25 vars, gitignored via `.env.*` with `!.env*.example` exceptions) plus `.env.production.example`. scripts/start.mjs no longer generates secrets; it validates the file and runs compose with `--env-file .env.production`. Old root `.env`/`.env.example` removed
- Env consolidated: root `.env` (local, 25 vars incl. POSTGRES_PASSWORD/MINIO_ROOT_PASSWORD used by dev compose) + root `.env.production` (VPS). server/.env and client/.env removed. Server scripts use `--env-file=../.env`; Prisma CLI via `npm run prisma -- <cmd>` because Prisma only auto-loads .env next to the schema
- VPS (luggora) already runs Nginx Proxy Manager on 80/443 plus other projects (gluesale, keepmymotivation). Decision: Caddy stays but sits behind NPM. Prod Caddy listens HTTP :80 only, automatic_https off, no host ports; joins external network `${PROXY_NETWORK}` (default guess nginx-proxy-manager_default) with alias `easyhost-caddy`. NPM terminates TLS (wildcard *.easyhost.fun via DNS challenge) and forwards all easyhost hosts to easyhost-caddy:80. User rejected letting the API drive NPM's API
- All storage is public by product decision (2026-09-25): every bucket gets an anonymous GetObject policy on creation, Bucket.isPublic removed (migration `make_storage_public`), no presigned URLs, no private toggle, v1 key-protected GET removed. Listings/uploads return each file's public `url`; buckets return `baseUrl`. Uploads/deletes/listing still require API key or dashboard login
- Databases switched from SQLite to shared Postgres (2026-09-26): `userdb` container (infra/userdb: postgres:16-alpine + first-boot script that creates a self-signed cert, turns ssl on, makes pg_hba `hostssl` for network connections, revokes CONNECT on postgres/template1 from PUBLIC). Each customer DB = `db_<hex>` owned by role `u_<hex>` (CONNECTION LIMIT 20, REVOKE ALL FROM PUBLIC), password stored in platform `Database` model. Console queries run as the owner role (never superuser), 15s statement timeout, 1000 rows. Connection string `postgresql://u_x:pw@USERDB_PUBLIC_HOST:USERDB_PUBLIC_PORT/db_x?sslmode=require`; prod host db.easyhost.fun:5432 published directly (not via NPM), dev 127.0.0.1:54330. Env: USERDB_PASSWORD, USERDB_URL, USERDB_PUBLIC_HOST, USERDB_PUBLIC_PORT. SQLite, better-sqlite3, SQLITE_DIR and v1 databases API removed. Migration `postgres_databases` needs to be run interactively by the user (drops sqlite_databases)
- Database page: connection string card (Show/Copy/Reset password, no ORM examples by user request) + tabs "Table editor" and "SQL console". Table editor: GET/PATCH /api/databases/:id/tables/:table/rows, 50 rows/page, every cell returned as ::text, click cell to edit (Enter saves, Esc cancels, NULL button for nullable), UPDATE by primary key with params; tables without PK are read-only
- Each customer DB also gets `<dbName>_shadow` (same owner role) so `prisma migrate dev` works without CREATEDB; dashboard shows both "Database URL" and "Shadow database URL". Roles intentionally lack CREATEDB
- userdb TLS: custom entrypoint infra/userdb/tls-entrypoint.sh. USERDB_TLS_MODE=self-signed (dev, generated on start) or files (prod: NPM's Let's Encrypt cert for db.easyhost.fun mounted read-only from NPM_LETSENCRYPT_DIR/live/USERDB_CERT_NAME, copied in with postgres ownership, re-checked every 6h and `pg_ctl reload` on change). Connection string sslmode from required env USERDB_PUBLIC_SSLMODE: dev no-verify, prod verify-full (pg verifies, no warning; Prisma engine treats unknown modes as prefer). Dashboard hints psql/GUI users to use sslmode=require
- Email senders: `EmailSender` model (username globally unique), max 10 per user (MAX_EMAIL_SENDERS), address = `<username>@EMAIL_DOMAIN` (required env, easyhost.fun). Reserved usernames in validations.ts. Send API requires `from` as a full sender address the user owns; no default sender. Platform emails (verify/reset) still use EMAIL_FROM
- App custom domains (2026-09-26): `AppDomain` model (hostname unique, PENDING/ACTIVE/FAILED, npmProxyHostId, npmCertificateId). User keeps NPM in front (rejected Caddy-as-front-door). Verify = dns lookup must include PUBLIC_IP, then (EDGE_PROXY=npm) NPM API: create LE certificate first, then proxy host to easyhost-caddy:80 (cleanup cert if host fails); removal deletes both. Caddy app route matches `<slug>.APPS_DOMAIN` + ACTIVE custom hosts via `routeApp` (server/src/lib/routing.ts, used by deploy/start/sync). API container joins NPM network (NPM_API_URL=http://nginx-proxy-manager_app_1:81). Dedicated NPM user with "Created Items Only" visibility recommended. Dev: EDGE_PROXY=none, PUBLIC_IP=127.0.0.1.
